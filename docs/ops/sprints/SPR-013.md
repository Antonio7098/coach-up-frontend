# Sprint SPR-013 — Per-group per-skill Assessments (post-triage, pre-summary)

Introduce an automatic assessments step that runs after triage and before summary. For each triage group (N) in the due slice, run per-skill assessments across M skills, yielding N × M assessments, and persist results via existing v2 assessment paths.

## Risks & Mitigations
- Risk: Cost/latency blow-up with N×M growth · Mitigation: caps (groups, skills, concurrency), timeouts, sampling, flag default off.
- Risk: Duplicate writes under retries · Mitigation: strict idempotency keys and checks; finalize guards.
- Risk: Cadence slowdown · Mitigation: best-effort step with short timeouts; summary proceeds on failure.
- Risk: Stale or misaligned groups vs. summary slice · Mitigation: align to cutoffIndex used by summary and triage.

## Technical Details
### Flow Placement (Cadence)
1. summaries.ensureJob determines a due summary window and cutoffIndex.
2. Run triage for slice (best-effort) [already in SPR-012].
3. Assessments step (this sprint):
   - Compute N triage groups for the slice (groupIds >= cutoffIndex, bounded by ASSESS_MAX_GROUPS).
   - Determine M skills (from profile/config; bounded by ASSESS_MAX_SKILLS).
   - Ensure an assessment group exists (create if needed) for the slice and session.
   - For each (group, skill), invoke v2 finalize path to persist a skill assessment.
   - Respect ASSESS_CONCURRENCY and ASSESS_TIMEOUT_MS; swallow failures and continue.
4. Generate summary using latest assessments when present; otherwise use existing behavior.

### API & Functions (reuse existing where possible)
- Next API
  - POST /api/assessments/run?sessionId=... → returns { groupId } (existing).
  - POST /api/assessments/convex/finalize (v2) → persists per-skill results and updates latestGroupId (existing).
- Convex
  - assessments:recordSkillAssessmentV2 (existing): validates bounds; writes doc.
  - assessments:getLatestAssessmentSummary (existing): exposes latest summary with latestGroupId.
  - assessments:checkFinalizeIdempotency / assessments:markFinalizeCompleted (existing guards).
- Orchestrator (new light glue)
  - If in Convex: action assessments:runForSlice(sessionId, cutoffIndex, limits) to batch finalize per (group, skill).
  - If in Next: lib/summaries.ts or lib/summarizer.ts invokes an assessments client right after triage.

### Database Models
- Collections/Tables: assessments (existing); optionally events (for audit/metrics).
- New/changed fields: none expected; confirm against existing v2 schema.
- Constraints/validation: unique key on (sessionId, groupId, skillHash, rubricVersion) for idempotency.
- Indexes: by_session, by_session_group_skill for fast lookups.
- Migrations: add index/unique constraint if missing; backfill N/A.
